# 产品定义

## 一句话定义

**帮助用户收集碎片信息（文本/图片/链接），附着自己的思考，并在未来需要时快速找回和取用。**

---

## 核心价值

### 不是什么
- ❌ 不是文件管理器（网盘）
- ❌ 不是浏览器书签
- ❌ 不是笔记软件
- ❌ 不是知识库

### 是什么
- ✅ **信息 + 思考** 的整理工具
- ✅ 强调"附着自己的思考"
- ✅ 强调"未来可快速找回"
- ✅ 强调"可直接取用"

---

## 产品目标

### 主路径（核心流程）
1. **收集** - 快速记录碎片信息
2. **附着思考** - 写下"为什么收集这个"
3. **找回** - 通过搜索快速定位
4. **取用** - 直接使用（复制/下载/跳转）

### 非目标（首版不做）
- ❌ 不做完整的输出工作流（如生成文档/PPT）
- ❌ 不做团队协作
- ❌ 不做知识图谱
- ❌ 不做 AI 自动总结（二期考虑）

---

## 用户画像

### 目标用户
- 产品经理、设计师、开发者、研究人员
- 需要大量收集碎片信息
- 需要在未来某个时刻快速找回

### 典型场景
1. **竞品分析** - 收集竞品截图 + 自己的分析
2. **技术学习** - 收集技术文章 + 自己的理解
3. **灵感收集** - 收集设计案例 + 自己的想法
4. **资料整理** - 收集各种资料 + 分类标注

## 核心约束

### 产品约束
1. **收集时必须附着思考**
   - 图片：必须填写"这张图说明了什么"
   - URL：必须填写"这篇文章的哪个观点值得记录"
   - 文本：可选填写思考

2. **所有素材必须可搜索**
   - 图片 → OCR 提取文字 → 索引
   - URL → 提取正文 → 索引
   - 文本 → 直接索引

3. **明确取用路径**
   - 图片 → 复制图片链接 / 下载
   - URL → 跳转原文
   - 文本 → 复制文本

### 技术约束
1. **存储限制**
   - 单文件最大 100MB
   - 图片最大 10MB
   - 每用户配额 10GB

2. **性能要求**
   - 搜索响应时间 < 500ms
   - 图片上传 + OCR < 10s
   - URL 元数据提取 < 5s

3. **安全要求**
   - 文件类型校验（MIME + 文件头）
   - 用户隔离（只能访问自己的文件）
   - URL SSRF 防护（禁止内网 IP）

## 差异化

### vs 网盘（如百度网盘）
- 网盘：存储文件，按文件夹分类
- 我们：存储信息 + 思考，按内容搜索

### vs 浏览器书签
- 书签：只保存 URL，按文件夹分类
- 我们：保存 URL + 网页内容 + 自己的思考，全文搜索

### vs 笔记软件（如 Notion）
- 笔记：结构化编辑，需要整理成文档
- 我们：碎片化收集，快速记录，延迟整理

### vs 稍后读（如 Pocket）
- 稍后读：临时存储，阅读后删除
- 我们：长期存储，附着思考，未来复用
