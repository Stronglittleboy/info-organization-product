# 1. 修订目标

基于《中保真交互稿 V1》的审查意见，仅修订 3 个点：
1. 收集页保存后反馈区降压
2. 待处理页弱化双 Tab，改为统一处理流
3. 专题页强化“持续问题”语义

本稿继续停留在设计阶段，不进入代码实施。

---

# 2. 全局原则（保持不变）

## 2.1 一级入口
- 收集
- 查找

## 2.2 二级/上下文入口
- 待处理
- 专题
- 详情

## 2.3 全局约束
1. 首版“用”= 复制原文 / 复制原文+思考。
2. 待处理页只承载 15 秒动作。
3. 专题是持续问题的稳定上下文，不是分类目录或工作台。
4. 收集页禁止工作台化。
5. 查找页禁止吞掉专题经营、深整理、输出系统。

# 3. 页面一：收集页（V1.1）

## 3.1 页面目标
最低摩擦完成录入，让“继续记录”始终是主路径。

## 3.2 页面结构

```text
顶部栏
├─ 页面标题：收集
├─ 一级切换：查找
└─ 右侧入口：待处理

主输入区
├─ 多行输入框
├─ 来源辅助入口（粘贴/链接/截图）
└─ 保存按钮（主按钮）

保存后反馈区（仅保存成功时出现）
├─ 已保存提示
├─ 主按钮：继续记录
├─ 次按钮：补一句思考
└─ 弱入口：更多处理（加入专题）

刚刚记录区
├─ 最近 3~5 条
└─ 每条支持：补一句思考 / 加入专题 / 详情

页底轻提醒
└─ 还有 N 条最近内容可去待处理继续处理
```

## 3.3 关键修订

### 修订点 A：保存后反馈区降压
旧版问题：
- 补一句思考 / 加入专题 / 完成 三个动作平权，容易让用户保存后立刻进入管理心态。

V1.1 调整：
- 主动作固定为：`继续记录`
- 次动作：`补一句思考`
- `加入专题`收进弱入口 `更多处理`

### 设计意图
保证奥野式第一原则：
> 先收进来，比先管理更重要。

## 3.4 页面状态
- 初始空状态
- 输入中状态
- 保存成功状态
- 刚刚记录非空状态

## 3.5 禁止事项
- 禁止统计大盘
- 禁止全量历史记录
- 禁止输出动作

# 4. 页面二：待处理页（V1.1）

## 4.1 页面目标
让系统自动判断每条最近内容当前最需要补的那一步，用户顺着流处理即可。

## 4.2 页面结构

```text
顶部栏
├─ 返回：收集
└─ 页面标题：待处理

提醒条
└─ 最近有 N 条内容还可以再变得更好用

统一处理流
└─ 条目卡片（单列）
   ├─ 内容摘要
   ├─ 来源与时间
   ├─ 当前建议动作提示
   ├─ 一句话思考输入区 或 已有思考展示
   ├─ 专题选择器（必要时出现）
   └─ 动作：保存 / 跳过 / 详情
```

## 4.3 关键修订

### 修订点 B：弱化双 Tab，改为统一处理流
旧版问题：
- “待补一句思考 / 待加入专题” 双 Tab 会强化系统状态感。

V1.1 调整：
- 移除双 Tab
- 由系统根据条目情况决定当前建议动作
- 用户只做顺序处理，不先切换状态分类

## 4.4 条目卡逻辑

### 情况 A：无思考
- 建议动作：补一句思考
- 主动作：保存
- 次动作：跳过 / 详情

### 情况 B：有思考但无专题
- 建议动作：加入专题
- 默认展示已有思考
- 主动作：保存
- 次动作：详情

### 情况 C：有思考且已入专题
- 不进入主待处理流

## 4.5 设计意图
待处理不是后台治理，而是：
> 把最近内容快速变成更属于自己的素材。

## 4.6 页面状态
- 列表为空：当前没有待处理内容
- 列表非空：按最近优先排序
- 跳过：条目后移

## 4.7 硬约束
- 每条卡片必须 15 秒内可完成
- 不出现大段正文编辑
- 不出现复杂状态筛选

# 5. 页面三：查找页（保持主结构，强调信息层级）

## 5.1 页面目标
找回过去内容，并直接拿走使用。

## 5.2 页面结构

```text
顶部栏
├─ 页面标题：查找
├─ 一级切换：收集
└─ 可选入口：相关专题

搜索区
├─ 搜索框
└─ 筛选条（时间 / 是否有思考 / 专题）

结果区
└─ 结果卡片列表
   ├─ 内容片段（第一层）
   ├─ 一句话思考（第二层）
   ├─ 次信息：专题 + 来源时间（第三层）
   └─ 动作：复制原文 / 复制原文+思考 / 详情

页底/侧下推荐
└─ 相关专题
```

## 5.3 信息层级硬约束
1. 内容片段
2. 一句话思考
3. 次信息（专题、来源、时间弱化呈现）
4. 动作按钮

## 5.4 页面状态
- 空搜索引导
- 有结果
- 无结果

## 5.5 禁止事项
- 禁止深编辑
- 禁止输出清单
- 禁止专题经营
- 禁止结果卡继续加密度

# 6. 页面四：专题页（V1.1）

## 6.1 页面目标
让用户感受到：这里不是分类器，而是围绕一个持续问题积累内容的地方。

## 6.2 页面定位
- 当前为二级页
- 一级候选，但本稿不提升

## 6.3 页面结构

```text
顶部栏
├─ 返回：查找 或 详情
└─ 页面标题：专题名称

专题说明区
├─ 一句话说明专题问题域
└─ 辅助说明：这里汇集你围绕这个持续问题积累的内容

专题内搜索区
└─ 搜索本专题内容

专题列表区
└─ 条目卡片
   ├─ 内容摘要
   ├─ 一句话思考
   ├─ 来源与时间
   └─ 动作：详情
```

## 6.4 关键修订

### 修订点 C：强化“持续问题”语义
旧版问题：
- 页面结构上虽正确，但用户感知上仍可能把专题看成筛选结果页。

V1.1 调整：
- 在专题说明区增加辅助说明
- 明确告诉用户：这是围绕一个持续问题积累的内容

### 示例文案
- “这里汇集你围绕【信息整理产品】持续积累的内容。”
- “当你反复思考这个问题时，相关素材会沉淀在这里。”

## 6.5 设计意图
专题的意义不是分类，而是：
> 为持续问题提供稳定上下文。

## 6.6 页面状态
- 专题为空
- 专题有内容
- 专题内搜索命中/未命中

## 6.7 禁止事项
- 禁止进度面板
- 禁止观点工作台
- 禁止输出中心
- 禁止文件夹树

# 7. 页面五：详情页（保持稳定）

## 7.1 页面目标
把单条素材搞清楚，并允许带走。

## 7.2 页面结构

```text
顶部栏
├─ 返回来源页
└─ 页面标题：详情

原文区
└─ 完整原文，可折叠/展开

来源区
├─ 来源类型
├─ 来源名称/链接
└─ 记录时间

思考区
├─ 标题：我的一句思考
├─ 文本内容或输入框
└─ 编辑入口

专题区
├─ 当前所属专题
└─ 更换专题

底部稳定动作区
├─ 复制原文
└─ 复制原文+思考
```

## 7.3 硬约束
- 复制动作必须位于底部稳定位置
- 不得漂移到信息块中
- 不得增加推荐流、历史复用、关系图、AI面板

---

# 8. 页面跳转关系（V1.1）

```text
收集
├─ 保存后留在当前页
├─ 主路径：继续记录
├─ 次路径：补一句思考
└─ 去待处理 / 详情

待处理
├─ 顺序处理最近条目
├─ 保存后进入下一条
├─ 跳过后条目后移
└─ 复杂情况 -> 详情

查找
├─ 结果 -> 详情
└─ 结果 -> 专题

专题
└─ 条目 -> 详情

详情
├─ 返回来源页
└─ 可更换专题 / 复制带走
```

# 9. 审查后定稿约束

## 收集页
- 保存后默认鼓励继续记录，不鼓励立即管理

## 待处理页
- 用户不先理解系统状态，只顺着当前建议动作处理

## 查找页
- 卡片密度封顶，不再继续加字段

## 专题页
- 必须让用户感知“持续问题”，不能只像另一个筛选页

## 详情页
- 保持单条澄清，不再加系统性能力
